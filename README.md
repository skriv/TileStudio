# Tile Studio — MVP

Браузерное приложение для точной раскладки плитки в трёх пилотных помещениях (Кухня, Туалет, Коридор) по плану квартиры, с 3D-просмотром и path-traced фоторендером. Источник истины по требованиям — `TILE_STUDIO_SPEC.md`.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # Vitest: ядро геометрии и раскладки
npm run build      # tsc -b + vite build → dist/
```

Нужен браузер с WebGL2 (Chrome / Edge / Safari 17+ / Firefox последних версий).

Исходные файлы лежат в `public/samples/` и копируются туда без изменений (контрольные суммы совпадают с оригиналами):

| Файл | Назначение |
| --- | --- |
| `public/samples/room_scheme.pdf` | пилотный план, кнопка «Пилотный план» |
| `public/samples/280.png` | розовая плитка 85×285 мм (170×570 px, портрет) |
| `public/samples/450.png` | одна плитка 450×450 мм с шахматным рисунком |

Свой план (PDF / PNG / JPG / WebP) загружается кнопкой «Импорт плана», свою плитку — «+ Загрузить» в библиотеке.

## Рабочий процесс

1. **Старт.** Приложение само открывает последний проект в 3D. Если Кухня, Туалет или Коридор ещё без контура, они строятся по внутренним линиям `room_scheme.pdf` (масштаб зафиксирован размерной линией кухни 2240 мм). Высота дверей на плане не указана: 2100 мм, в карточке проёма стоит пометка «предположение». Окно кухни — 1233 мм, подоконник 1000 мм, высота 1000 мм. Кнопки «Кухня», «Туалет», «Коридор» над 3D переключают камеру на комнату.

   Свой план по-прежнему можно загрузить («Импорт плана») и обвести заново. Колесо — масштаб, правая/средняя кнопка или Alt+перетаскивание — панорама.
2. **Калибровка.** Инструмент «Калибровка»: две точки на известном размере (например, размерная линия 2240 мм кухни), ввести длину в мм, «Применить». Инструмент «Контроль» сравнивает второй размер и предупреждает при отклонении больше 1%.
3. **Обводка.** Выбрать помещение слева, «Обвести контур». Клики ставят вершины, есть привязка к вершинам и ортогональная привязка (Shift её отключает). Контур замыкается кликом в первую точку или Enter; Backspace удаляет последнюю точку, Esc отменяет. После этого вершины можно перетаскивать, двойной клик по ребру вставляет вершину, Shift+клик или правый клик удаляет её. Координаты и длины стен можно ввести числами в таблице справа. Есть быстрый прямоугольник по размерам.
4. **Подтверждение.** «Подтвердить контур» проверяет самопересечения и площадь, после чего создаются пол, стены (высота по умолчанию 2400 мм, редактируется) и потолок.
5. **Проёмы.** Выбрать стену, «+ Окно» / «+ Дверь», задать отступ, ширину, низ и высоту. Высота дверей помечается как «предположение»: на плане её нет, по умолчанию 2100 мм.
6. **Зоны прямо в 3D.** Если в проекте уже есть подтверждённое помещение, приложение открывается сразу в 3D. «✏ Обвести зону» включает рисование, камера на это время заблокирована.
   - Ведите мышью с зажатой кнопкой по стене или полу: после отпускания контур замкнётся и станет зоной.
   - Или кликайте по точкам: Enter или клик в первую (белую) точку замыкает контур.
   - Точки привязываются к краям поверхности (40 мм). Окна и двери вычитаются из зоны автоматически.

   Затем нажмите на плитку в библиотеке — она применится к выбранной зоне.

   Другие способы создать зону: на стене или полу — «Вся поверхность», прямоугольник по координатам или в «Развёртке» мышью (прямоугольник / многоугольник, привязка 5 мм, к углам и проёмам). Новая зона создаётся **без материала**.
7. **Назначение плитки.** Выбрать зону, нажать на плитку в списке «Материал зоны». Дальше настраиваются поворот, шов и цвет шва, якорь (угол или центр), стартовое смещение, смещение рядов (½, ⅓) и угол сетки. Статистика показывает целые и подрезанные плитки. «Снять плитку» возвращает зону в нейтральное состояние.
8. **3D.** Вкладка «3D»: виды «Обзор» / «Сверху» / «Глаза» (1600 мм) / «Фокус зоны» (F). Можно скрыть потолок или выбранную стену, сохранить ракурс, экспортировать PNG/JPG текущего кадра. Клик по поверхности в 3D выбирает зону.
9. **Фоторендер.** Вкладка «Рендер» берёт текущий ракурс 3D. Path tracing накапливает сэмплы до заданного числа (по умолчанию 256), его можно остановить или продолжить. «PNG» / «JPG» сохраняют реальный кадр в разрешении из настроек (по умолчанию 1920×1080).
10. **Сохранение.** Автосохранение в IndexedDB (с исходными файлами плана и плитки в виде Blob), «Проекты…» для переключения между ними. «Экспорт проекта» создаёт ZIP (`project.json`, `manifest.json`, `assets/`), «Открыть файл» импортирует его.

Горячие клавиши: Cmd/Ctrl+Z — отмена, Shift+Cmd/Ctrl+Z или Ctrl+Y — повтор, 1/2/3 — План / 3D / Рендер.

## Архитектура

```

src/core/project/    types.ts (schemaVersion), defaults.ts, serialize.ts (миграции, без blob: URL)
src/storage/         db.ts (IndexedDB), archive.ts (ZIP)
src/state/store.ts   zustand: действия, undo/redo, автосохранение
src/features/plan-editor/  PlanEditor.tsx (SVG), pdf.ts (pdf.js)
src/features/zones/        SurfaceEditor.tsx — развёртка поверхности с реальными плитками
src/features/viewport/     sceneBuilder.ts — ОДНА функция сборки сцены для 3D и рендера; Viewport3D.tsx
```

### Ядро раскладки (`src/core/tiling/layout.ts`)

- Все размеры в миллиметрах; в метры для Three.js переводит только `mmToM` (÷1000).
- Шаг сетки равен `(footprintW + шов, footprintH + шов)`, где footprint — размер плитки с учётом поворота 0/90/180/270. Плитка не растягивается и не масштабируется.
- Начало сетки — угол зоны или центр (центр плитки в центре зоны) плюс смещение по u/v. Есть смещение рядов ½ / ⅓ и поворот всей сетки на произвольный угол.
- Для каждой позиции сетки берётся прямоугольник плитки:
  - если он целиком внутри области, плитка считается целой;
  - иначе он **геометрически** пересекается с областью (`polygon-clipping`) и триангулируется (`earcut`).
- UV каждой вершины считаются **относительно полной плитки**: у подрезки видна ровно соответствующая часть изображения. Поворот изображения учитывается функцией `footprintToImageUV`.
- Область зоны = зона ∩ поверхность − проёмы − более поздние зоны на той же поверхности.
- Швы — это реальная геометрия: под плитками лежит слой цвета шва, а плитки отстоят друг от друга на ширину шва. Швы не нарисованы в текстуре и не построены через `texture.repeat`.
- `450.png` считается **одной** плиткой 450×450: весь шахматный рисунок лежит на одной плитке, швы идут через 450+g мм.
- `280.png` (170×570 px) — портрет 85×285 мм; при назначении по умолчанию ставится поворот 90°, то есть горизонтальная укладка 285×85.

### Тесты (`npm test`): 27/27 проходят

- **Пример A: 2500×2500, плитка 500.**
  - Без шва: 25 целых.
  - Шов 2 мм от угла: 5×5 позиций, последний ряд и столбец подрезаны.
  - Шов 2 мм по центру: подрезка симметрична с обеих сторон.
- **Пример B: ширина 900, плитка 450.** Без шва 2 целых в ряду; со швом 2 мм появляется подрезка (нужно 902 мм).
- **450.png:** одна плитка, а не 9; швы только через 450+g.
- **280.png:** пропорция 170×570 соответствует 85×285; поворот 90° даёт footprint 285×85 без кропа.
- **UV:** обратимость для всех поворотов; половинная подрезка показывает половину изображения; смещение начала меняет видимый фрагмент.
- **Окно в стене:** подрезка вокруг проёма, площадь сохраняется, UV частичные.
- **Сетка:** смещение рядов ½, повёрнутая сетка (сохранение площади), детерминированность ID, отказ без физического размера.
- **Геометрия помещения:** нормали стен внутрь для обоих направлений обхода и Г-образной комнаты, немиррированная система координат пола, вычитание проёмов, порядок зон, стабильность ID стен при редактировании контура.

## Решения и допущения

- Моделируются только три пилотных помещения; другие помещения и мебель отсутствуют. Размеры не выдумываются: контур обводится по плану после калибровки или вводится числами.
- Высота потолка по умолчанию 2400 мм и меняется у каждого помещения.
- Высота дверей на плане не указана: используется 2100 мм с флагом «предположение», который виден в интерфейсе.
- Окна: подоконник 1000 мм и высота 1000 мм по умолчанию, редактируются. В 3D у проёмов есть откосы глубиной 160 мм, у окон — рама и подоконник.
- Система координат стены: u идёт вправо, если смотреть на стену изнутри помещения, v — вверх от пола. Развёртка и 3D используют одну и ту же систему, поэтому раскладка на них совпадает.
- Зоны статичны: изменить или удалить их границы можно только в режиме «Редактировать зоны». Смена материала геометрию зоны не трогает, и это проверено.
- Плитки никогда не назначаются автоматически: при загрузке они попадают только в библиотеку.
- Отделка (глянец / сатин / мат) задаёт roughness и clearcoat в PBR-материале. Карта нормалей не используется, так как исходники — только цветовые изображения.
- Освещение 3D: environment (RoomEnvironment) + потолочный свет в каждом помещении + солнце с азимутом и высотой, мягкие тени. Фоторендер: прямоугольный потолочный светильник (area light), солнце и процедурное небо, видимое в окне.

## Фоторендер и ограничения GPU / браузера

- Используется [three-gpu-pathtracer](https://github.com/gkjohnson/three-gpu-pathtracer) на WebGL2 со своим WebGLRenderer. Сцену собирает тот же `buildScene`, что и 3D-просмотр, поэтому геометрия и UV одинаковы.
- На Apple M-серии кадр 1280×720 рендерится примерно со скоростью 6–7 сэмплов/с: 64 сэмпла за ~10 с, 256 сэмплов за ~40 с. Слабые и интегрированные GPU работают медленнее, при большом разрешении возможен сброс контекста WebGL.
- Если path tracing не запустился (нет WebGL2 / float-текстур, ошибка драйвера), выводится ошибка и предлагается «растровый кадр». Он явно подписан как **«НЕ path tracing»**.
- Максимальный размер экспорта ограничен `MAX_TEXTURE_SIZE` / `MAX_VIEWPORT_DIMS` устройства.

## Не реализовано (честно)

- Перспективная коррекция фото плана (только PDF или ровные сканы; калибровка масштабная, по двум точкам).
- Ортографическая камера: вид «Сверху» — перспективный с узким углом обзора.
- Общие проёмы между помещениями не синхронизируются: дверь между кухней и коридором нужно добавить в каждом помещении.
- Стекло в окнах (проём открыт на небо), толщина и фаска плиток, затирка с рельефом.
- Отчёт о количестве плиток для закупки и экспорт раскладки (CSV / PDF): в интерфейсе есть только статистика целых и подрезанных плиток по зоне.
- E2E-тесты (Playwright): проверка интерфейса выполнялась вручную в браузере, автоматические тесты — только на ядро (Vitest).
- Денойзер для фоторендера: качество достигается числом сэмплов.
